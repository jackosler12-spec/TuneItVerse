# TuneItVerse ECU Database

Machine-readable ECU family metadata. Embedded at compile time by `src-tauri/src/ecu_database.rs`.

## Schema (index 1.26)
Every family JSON has `ecu_family`, `sources` (cited), `hardware_tested` (always `false` until a bench session is logged) and `capabilities`:

```json
"capabilities": {
  "identify": {"status": "verified_dump", "source": "..."},
  "read": {...}, "checksum": {...}, "seed_key": {...}, "write": {...}, "map_hints": {...}
}
```

`status` must be one of: `verified_dump`, `verified_log`, `public_source`, `reference_doc`, `experimental`, `report_only`, `unverified`, `not_supported`. `source` is required for every capability. The loader validates each entry at startup and drops any that fail; Scripts → Self-check lists the errors. `index.json` status strings are generated from the capabilities.

`gm_osid_map.json` maps GM OS IDs to a PCM type. It is generated by `scripts/gen-gm-osid-map.mjs <PcmInfo.cs> <commit sha>` from PcmHammer and records the source commit.

## How to add a family
1. Create `reference/ecu_database/<family>.json` with **cited public sources** and a full `capabilities` block.
2. Add it to `DB_FILES` in `src-tauri/src/ecu_database.rs`.
3. Update `index.json` and this README.
4. Run `cargo test --lib`. The schema tests fail on a missing source or status.
5. Personal dumps only — no commercial bins. Never invent addresses, keys, seed/key algorithms or DID meanings.

## Live write path
Only `P01_0411` is in `write_families()`. Guided write still requires FullImage backup, voltage gate, OS/chip match, and (for the kernel path) `experimental_p01_write` + typed confirmation. **Not bench-tested.** EDC16C41 has measured seed/key but checksum is report-only and write is off.

## Honesty
Do not claim "fully operational" for a family without measured checksums, a logged or cited flash session, and a FullImage backup path. Catalog entries without those are identify / offline-tools only.
